# Codex Pulse Monitor

Codex 请求级监控的原生 macOS 菜单栏应用。它保留原 Codex Pulse 的额度展示，并新增每个已完成 Codex turn 的性能与 Token 记录。

## 记录字段

- 首 Token 延迟（`time_to_first_token_ms`）
- 总耗时（`duration_ms`）
- 模型与思考等级（`model` / `effort`）
- 输入、缓存输入、输出、推理输出和总 Token
- Codex turn ID、开始时间和来源会话文件

记录保存在 `~/Library/Application Support/Codex Pulse/requests.jsonl`。程序只读取 Codex 已生成的本地会话事件，不保存提示词、回复正文、工具参数或隐藏思维内容。

## 构建与运行

```sh
chmod +x build.sh
./build.sh
open "../Codex Pulse Monitor.app"
```

菜单每 30 秒自动刷新；也可按 `⌘R` 手动刷新。首次启动会导入 `~/.codex/sessions` 与 `~/.codex/archived_sessions` 中的历史指标，之后按 turn ID 去重，并通过持久化的文件修改时间只重读发生变化的会话文件。首次全量导入可能短暂占用较多 CPU，完成后会回落。

Token 数字会自动使用 `K`、`M`、`B` 紧凑显示。点击菜单中的“统计面板…”（`⌘D`）可打开原生统计窗口，支持：

- 今日、最近 7 天、最近 30 天或全部时间；默认显示今日数据
- 按模型和推理等级筛选
- 模型调用数、总 Token、典型首响应和较慢请求总耗时
- 缓存命中率与推理 Token 占比
- 每日 Token 趋势
- 按“模型 × 推理等级”拆分的性能与用量明细
- 按 OpenAI 官方标准 API Token 价格估算的“价值相当于”，覆盖概览、模型明细和实时控制台

统计窗口还包含“实时控制台”页签：窗口打开时每 2 秒读取一次发生变化的 Codex 会话文件，进行中的请求置顶显示，并持续更新模型、推理等级、已用时间和最新 Token。历史事件缺少独立模型上下文时，程序会使用同一会话最近一次明确的模型设置回填，并自动修复旧记录中的“未知”。

统计术语使用直观名称：

- “典型首响应”表示一半请求的首响应时间不超过该值。
- “较慢首响应/耗时”表示 95% 的请求不超过该值。
- 每日 Token 柱状图支持鼠标悬浮，显示日期、模型调用数、紧凑值和完整 Token 数。
- 柱状图使用自动取整的纵轴 Token 刻度，不再在峰值柱顶显示数字。
- 非基线网格使用低对比度绘制，避免抢过柱状数据的视觉层级。
- “统计概览”的模型分组表格正文统一采用左对齐，便于按列扫描比较。

“今日”按本地时区当天 00:00 起统计；最近 7 天和最近 30 天也按包含今天在内的自然日计算。

## 替换旧版

先退出菜单栏里的旧 Codex Pulse，再把构建出的 `Codex Pulse Monitor.app` 放入 `/Applications`。新版本使用独立 Bundle ID，不会覆盖旧版偏好；确认运行正常后再删除旧版即可。

## 指标口径

这里的“一次请求”是一次 Codex turn，也就是用户提交后到该 turn 完成为止。一次 turn 内可能包含多轮模型调用和工具执行。Codex 的 `total_token_usage` 会在整个会话中持续累计，因此程序使用本 turn 完成时累计值减去 turn 开始前累计值，得到该请求真正新增的 Token；不能直接把累计值当成单次请求用量。

从 v2.5.0 起，程序首次启动会自动重新扫描历史会话并修复此前按会话累计值保存的请求记录，避免 Token 和 API 估算价值被重复累计。

从 v2.6.0 起，“模型调用数”按每条具有非零 `last_token_usage` 的 `token_count` 事件统计。它表示实际产生 Token 的底层模型调用次数；一个 Codex turn 通常包含多次模型调用。升级后会自动重扫历史会话补齐这一字段。

“价值相当于”使用 2026-07-14 查询到的 OpenAI 标准 API 文本 Token 单价：非缓存输入、缓存输入和输出分别计价；缓存 Token 是输入 Token 的子集，推理 Token 是输出 Token 的子集，因此不会重复收费。`codex-auto-review` 依据官方 Codex 说明按 GPT-5.3-Codex 价格映射；没有可匹配 OpenAI 官方价格的第三方或未知模型显示 `--`。现有日志只保存整个 turn 的累计 Token，无法判断每次底层模型调用是否超过 272K 输入，因此不叠加长上下文倍率。此数值只表示同等 Token 用量按标准 API 基础费率计算的估算价值，不是 ChatGPT/Codex 订阅的实际账单，也不包含工具调用、快速模式、区域处理等附加费用。
