# Codex Pulse Monitor

Codex 请求级监控的原生 macOS 菜单栏应用。它保留原 Codex Pulse 的额度展示，并新增每个已完成 Codex turn 的性能与 Token 记录。

## 记录字段

- 首 Token 延迟（`time_to_first_token_ms`）
- 总耗时（`duration_ms`）
- 模型与思考等级（`model` / `effort`）
- 输入、缓存输入、输出、推理输出和总 Token
- Codex turn ID、开始时间和来源会话文件

turn 汇总保存在 `~/Library/Application Support/Codex Pulse/requests.jsonl`，单次 API 调用指标保存在同目录的 `api-calls.jsonl`。程序只读取 Codex 已生成的本地会话事件和本地线程标题；不会把提示词、回复正文、工具参数、隐藏思维内容或完整会话标题写入指标文件。

## 构建与运行

```sh
chmod +x build.sh
./build.sh
open "../Codex Pulse Monitor.app"
```

菜单每 30 秒静默刷新；仅首次启动时菜单栏数字显示 `loading`，初始数据完成前不会打开浮窗。后续自动刷新和手动刷新都保留当前界面，完成后直接更新数字。首次启动会导入 `~/.codex/sessions` 与 `~/.codex/archived_sessions` 中的历史指标，之后按 turn ID 去重，并通过持久化的文件修改时间只重读发生变化的会话文件。首次全量导入可能短暂占用较多 CPU，完成后会回落。

菜单栏浮窗显示 7 天额度、重置卡以及“今日调用 / 今日 Token / 今日估值”；点击浮窗外部会自动收起。ChatGPT 订阅续费日期目前没有公开、稳定的 Codex 账户接口，因此应用不显示或推算续费日期。

额度与重置卡详情使用当前 Codex 登录凭据只读获取：额度响应短暂缓存 90 秒，并持久保留 30 分钟内的最近成功值；显示缓存时会在后台重试，不阻塞或清空浮窗。重置卡数量和真实到期时间缓存 5 分钟，网络失败时最多沿用 30 分钟内的最近成功值。旧版 `app-server` 协议保留为额度回退路径，登录 Token 不会写入参数、日志或应用数据。

浮窗底部显示“Tibo · 重置消息”。后台每 1 小时采集一次公开主帖与回复；点击 Tibo 卡片或顶部的刷新按钮会立即检查。帖子按真实 ID 去重，并把来源能提供的正文、类型、真实日期和链接交给模型。直接来源不可用时，使用 [Codex Reset Alerts 的公开转录](https://t.me/s/codexresetalerts) 作为备用：只提取明确署名 Tibo 的引文与唯一原帖链接，日期来自原帖 ID，不采纳频道自己的预测或评论；界面标记“公开转录分析”，且不保证覆盖完整时间线。模型用简体中文概括最近有关额度重置、重置卡、恢复用量的消息，区分已实施、计划、暗示和旧消息；无相关证据时明确限定为“本批取得的帖子未发现公告”。客户端不筛选 Reset 关键词，不推测人物状态或位置。镜像并不保证覆盖完整时间线。

点击“Tibo 动态”旁的设置按钮可配置任意 OpenAI Chat Completions 兼容服务，包括 Base URL、API Key 和模型。应用可通过兼容的 `GET /models` 接口自动拉取模型列表，也允许手动输入模型 ID。Base URL 与模型保存在本地偏好，API Key 以 AES 加密文件保存在应用支持目录，不访问 macOS 钥匙串；应用也不读取 `DEEPSEEK_API_KEY` 或其他 AI 环境变量。

自动检查时，成功分析的证据未变化就只更新检查时间，不调用 AI。跨轮次帖子缓存保留曾取得的记录，镜像短暂缺帖不会造成重复分析。自动检查间隔为 1 小时，新证据合并后最多每 30 分钟调用一次 AI。手动刷新会立即显示检查状态，解除认证暂停和失败退避，并允许对相同证据重新分析；仍保留每个 UTC 日最多 24 次的请求预算，连续点击只合并为一次待执行重试。来源临时失败时，手动重试可使用 14 天内的缓存帖子，并明确标记“缓存帖子分析，未确认最新动态”；来源与缓存都没有有效帖子时不调用 AI，显示本次来源错误，不沿用旧的认证错误。计数与重试时间跨重启保留。自动请求失败按 30 分钟、1 小时、2 小时等退避，最长 6 小时；HTTP 400/401/402/403/404 暂停自动请求，点击刷新或重新保存 AI 配置可重试，日上限仍有效。首次失败显示中文提示，已有中文结果则保留。模型返回的来源 ID 必须属于输入帖子，“查看”打开核心结论原帖。

AI 分析仅使用最近 14 天的有效帖子，历史记录仍保留在本地缓存中。证据 JSON 使用紧凑格式，旧帖在前、新帖追加，当前时间放末尾以保持前缀稳定；实际服务端缓存命中由供应商决定。DeepSeek 关闭隐藏推理，输出上限 512 Token。单次请求 JSON 超过 96 KB 则拒绝调用，不静默截断证据。摘要与查询缓存分别为 `tibo-reset-activity-v2.json`、`tibo-query-cache.json`。AI 审计日志 `~/Library/Application Support/Codex Pulse/tibo-ai-calls.jsonl` 记录检查与请求开始/结束、模型、请求 ID、正文大小、帖子数、HTTP 状态、耗时、成功与否、结果校验错误类别及供应商返回的完整 usage（含可用的缓存/推理 Token）。不记录密钥、请求正文或回复正文；无 usage 的失败不会伪造为零 Token。

Token 数字会自动使用 `K`、`M`、`B` 紧凑显示。点击菜单中的“统计面板…”（`⌘D`）可打开原生统计窗口，支持：

- 分层统计首页：突出总 Token、估算价值和 API 请求，效率指标使用紧凑的次级信息带
- 统计窗口打开时每 2 秒检查会话变更；概览包含进行中会话已上报的 Token，并单列进行中的调用数，未完成的调用不计入最终耗时或估算价值
- 今日、昨天、前天、最近 7 天、最近 30 天、全部时间或精确到秒的自选起止范围；默认显示今日数据
- 按模型和推理等级筛选
- 模型调用数、总 Token、典型首响应和较慢请求总耗时
- Token 速率、缓存命中率与推理 Token 占比
- 每日 Token 趋势
- 按“模型 × 推理等级”拆分的性能与用量明细
- 按每次调用的模型、服务档位和上下文长度估算“价值相当于”，覆盖概览、模型明细和实时控制台；未定价调用单独标记
- 实时 API 请求页按每次底层模型 API 调用逐行显示，不再按 turn 汇总；进行中的调用固定置顶
- 实时 API 请求页显示标准 / Fast / Ultra 档、首 Token、单次模型调用总时长和 Token 速率；`priority` service tier 显示为 Fast
- 新版会话 JSONL 缺少服务档位时，后台增量读取 Codex 本地运行日志的 `feedback_tags`，按会话、turn 和请求时间补齐真实档位；可确认的历史调用也会自动修复。Fast 同时显示闪电图标与文字，不使用当前全局设置推算历史调用。
- “概览 / 实时”使用短标题；指标简写为“调用、Token、估值、首响 P50、耗时 P95、速率”等，详细解释保留在悬浮提示中
- 实时页将 16 个窄列整理为事件、会话、模型、耗时 / 速率、Token 和估值 6 组；思考等级与加速图标归入模型，输入/缓存/输出/推理与总量归入 Token
- 列表通过“类型”区分普通模型调用和上下文压缩；新版 Codex 的 `token_usage_record` 作为压缩用量的权威来源，并将可确认的压缩 Token 与等价花费计入统计
- 紧凑显示时间、会话标题前缀、模型、推理等级、单次 Token 和估算价值
- 每页 100 条，并使用 `NSTableView` 可复用可见单元格，避免大量历史数据阻塞界面
- 首页新增 API 调用时使用行级滑入/淡入动画，不整表闪烁刷新
- 实时刷新会先按调用 ID 去重；检测到重复 ID 或不安全的顺序变化时自动降级为整表刷新，避免增量动画触发崩溃
- 实时控制台区分请求配置模型与响应明确报告的上游模型；两者不一致时以双层橙色提示和“模型不一致”标签展示，未取得响应字段时不作猜测
- 根据本地事件显示“已完成”，并推断进行中的“请求中 / 响应中 / 工具中”状态，在同一时间序列中高亮显示
- 会话日志按已处理字节位置增量解析；源文件删除、归档或连续 5 分钟无更新时清理对应的临时进行中记录。概览只在已完成用量或进行中会话发生相关变化时于后台重算，页签切换不做全量统计
- API 调用按包含年份的完整时间倒序排列；今天只显示时间，今年其他日期省略年份，跨年记录显示完整年份

统计窗口还包含“实时”页签：窗口打开时会持续读取发生变化的 Codex 会话文件。每条具有非零 `last_token_usage` 的 `token_count` 事件显示为一笔独立 API 请求；页面从 Codex 本地线程数据库读取会话标题，但仅在界面截短显示。进行中状态由 task、模型输出、工具调用和 `token_count` 的本地事件顺序推断。历史事件缺少独立模型上下文时，程序会使用同一会话最近一次明确的模型设置回填，并自动修复旧记录中的“未知”。每个 turn 的第一次模型调用使用 Codex `task_complete.time_to_first_token_ms` 作为精确首 Token；后续调用的首响应和所有单次调用总时长依据请求开始、首个模型响应、最后模型响应的本地事件边界推算，并以 `≈` 标识。非流式或仅有用量事件的调用缺少响应边界时，以对应权威用量记录或用量回报时间作为结束，仍标为估算；工具执行时间不并入已结束的模型调用。新版 Codex 在上下文压缩前写入的 `token_usage_record` 包含完整输入、缓存、输出和推理用量，程序优先采用该权威记录；压缩没有独立首 Token 观测，但可用单次总耗时计算速率。旧版日志若只有压缩后的总 Token 而没有用量拆分，则速率和估值显示 `--`，不猜测输出量或消费。无法可靠关联的旧记录也显示 `--`，不会拿整个 turn 的时长冒充单次调用时长。

统计术语使用直观名称：

- “首响 P50”表示一半请求的首响应时间不超过该值。
- “首响 P95 / 耗时 P95”表示 95% 的请求不超过该值。
- “速率”按输出 Token ÷ 单次调用总耗时计算，单位为 `tk/s`，包含首 Token 等待时间，而不是纯出字吞吐。普通流式、非流式与压缩使用同一口径，无需首 Token 时间戳；推理 Token 已包含在输出中，不重复相加。概览和模型分组使用总输出 Token ÷ 对应调用总耗时之和，而非逐条速率的算术平均。已知输出为零的调用按 0 计入；缺少正耗时或输出拆分的记录不计入，单条显示 `--`，未完成调用不预估速率。
- 速率文字在概览、模型分组及实时列表使用同一红→绿渐变：≤20 tk/s 固定最红，40 为及格线（橙色），≥60 为正常（浅绿），≥90 固定最绿。数值保留，未知速率显示灰色 `--`；着色只处理可见标签，不增加历史聚合或刷新频率。
- 每日 Token 柱状图支持鼠标悬浮，显示日期、模型调用数、紧凑值和完整 Token 数。
- 柱状图使用自动取整的纵轴 Token 刻度，不再在峰值柱顶显示数字。
- 非基线网格使用低对比度绘制，避免抢过柱状数据的视觉层级。
- “统计概览”的模型分组表格正文统一采用左对齐，便于按列扫描比较。

“今日”按本地时区当天 00:00 起统计；最近 7 天和最近 30 天也按包含今天在内的自然日计算。

## 替换旧版

先退出菜单栏里的旧 Codex Pulse，再把构建出的 `Codex Pulse Monitor.app` 放入 `/Applications`。新版本使用独立 Bundle ID，不会覆盖旧版偏好；确认运行正常后再删除旧版即可。

## 指标口径

这里的“一次请求”是一次 Codex turn，也就是用户提交后到该 turn 完成为止。一次 turn 内可能包含多轮模型调用和工具执行。Codex 的 `total_token_usage` 会在整个会话中持续累计，因此程序使用本 turn 完成时累计值减去 turn 开始前累计值，得到该请求真正新增的 Token；不能直接把累计值当成单次请求用量。

从 v2.5.0 起，程序首次启动会自动重新扫描历史会话并修复此前按会话累计值保存的请求记录，避免 Token 和 API 估算价值被重复累计。

从 v2.6.0 起，“模型调用数”按每条具有非零 `last_token_usage` 的 `token_count` 事件统计。它表示实际产生 Token 的底层模型调用次数；一个 Codex turn 通常包含多次模型调用。升级后会自动重扫历史会话补齐这一字段。

“价值相当于”使用 2026-09-23 查询到的 [OpenAI 官方 API 价格](https://developers.openai.com/api/docs/pricing)，并于 2026-09-30 补充 [GPT-6.1 Sol 官方价格](https://developers.openai.com/api/docs/models/gpt-6.1-sol)：每次底层调用分别按非缓存输入、缓存输入、输出计价；缓存 Token 是输入的子集，推理 Token 是输出的子集，不重复收费。覆盖 GPT-6.1 Sol、GPT-6 Astra/Sol/Luna、GPT-5.6 Sol/Terra/Luna 等模型。GPT-6.1 Sol 的标准档输入／缓存输入／输出分别为每百万 Token $2／$0.10／$10；`default` 按标准档，`priority` / `fast` 按 Fast 档（标准档的 2 倍）；GPT-6.1、GPT-6 与 GPT-5.6 系列输入超过 272K Token 时按官方长上下文倍率计算整次调用（输入与缓存 2 倍，输出 1.5 倍）。旧记录若没有 service tier，暂按标准档估算。Ultra Fast 目前是[限量预览](https://openai.com/index/previewing-ultrafast/)，官方未公布单价，因此这类调用不会套用标准或 Fast 价格。第三方渠道（如 `zai-org/GLM-5.3-Flash`）若无法确认实际计费服务商，也不冒用 OpenAI 价格。遇到未定价调用，汇总显示已知部分的下限（`≥`）或“未定价”。它不是 ChatGPT/Codex 订阅的实际账单；本地日志无法识别的缓存写入、工具调用和区域处理等费用未计入。

额度卡中的环形图显示额度剩余比例，横向进度条显示当前重置周期已经过去的时间比例；周期进度根据窗口时长和服务端返回的重置时间计算。
